# CHECKS: dreamteam's durable checks (systemd user timers on familiar and katana)

This file follows the fleet rule (Sen 11/14, the shape money and realmwatch use). Each timer's job ends by writing ONE
fixed-shape line:

    CHECK <name> <ok|warn|fail> · <fact, number, time> · <next/owner>

- **Exactly three segments.** The Watch (plan `checks.py`, `LINE`) takes the fact as everything up to the FIRST ` · `,
  so a fact never contains ` · `. `scripts/lib/check-line.sh` (and `check_line()` in `issues-queue.py`) turns any
  ` · ` in a fact into `, `, any other `·` into `,` (no `·` is left in a fact, so none can form a separator at
  either edge), and any newline into a space. A status other than ok, warn or fail is published as `fail`.
- **Where it goes:** to `~/.local/state/checks/<name>.line` on the host that ran it. The audit and issues-queue also
  print it to stdout (their journal); the briefing, the nightly guard's own runs and retire-pilot do not (the nightly's
  no-work path is silent by contract); `overnight-guarded.sh --check-line` prints exactly the text that call published
  (returned by the publisher itself, never re-read from the file), and nothing when it published nothing. Off familiar, the
  name gets `-<host>` (`check_name`). A name the Watch would not read (`[a-z0-9][a-z0-9-]{0,63}`) is never published.
- **How it is written:** a unique, exclusively created temp file in the same dir, then `mv -T` (Python:
  `os.replace`). A symlink at the destination is replaced and never followed, a directory there is refused,
  overlapping writers never share a temp file, and a reader never sees half a line. Tests never touch real home or check state:
  `tests/run.sh` creates ONE private dir and runs every suite with HOME, `XDG_CONFIG/STATE/DATA/CACHE_HOME` and
  `DREAMTEAM_CHECKS_DIR` inside it (inherited values are replaced; its cleanup only ever removes that dir), and runs
  no suite if it cannot make it. The mutation harness gives every mutant the same isolation. (2026-11-17: a mutant of
  an earlier runner kept an inherited checks dir, and its cleanup deleted familiar's real `~/.local/state/checks`.)
  The new line tests run their scripts from private fixture roots, so a lost `DREAMTEAM_STATE` override falls back
  into the fixture. Known residual: older suites (e.g. `test-overnight-guarded.sh`) run scripts with the real
  checkout as `CLAUDE_PLUGIN_ROOT` and pass a temp `DREAMTEAM_STATE`, so a mutant dropping that override would write
  the checkout's `state/` (a working tree, not `~/.local/state`).
- **How it is read:** Hearth › Checks reads each line with its mtime, and turns it amber once it is older than its
  cadence plus half.
- **Unknown is never ok:** a check that could not measure prints `fail` with the reason.
- **katana's rows are not on the Watch yet.** The Watch reads only familiar's folder. A row whose host is katana shows
  "on katana, not read here" until katana pushes its lines to familiar. That push is designed in plan
  `docs/FRICTION.md` 2026-11-16 08:5x (rule 2: a small timer on each host rsyncs its line files into familiar's
  `~/.local/state/checks/hosts/<host>/`) and not built. katana's lines are real and land in katana's own folder.
